# Planning Patterns（规划模式）

在目标卡获得确认、用户选择输出模式后完整读取本文件。根据目标选用内容，不要把全部模式叠加到一条路线。

## 目录

- 目标类型
- 第一性原理拆解
- 探索型目标
- 商业与外部结果
- 高风险领域修正
- 依据选择与时效
- 具体内容深度
- 以做促学
- 学习有效性闭环
- 学习方法选择与负荷控制
- 路线与阶段契约

## 目标类型

为路线选择一个主要 `goal_type`。目标跨类型时，只把直接阻塞最终成果的次要能力作为辅助主题。

| goal_type | 适用目标 | 优先诊断 | 优先依据 | 主要产出与验收 |
|---|---|---|---|---|
| `exam-certification` | 考试、证书、等级认定 | 大纲分项题或代表性样题 | 当前官方大纲、权重、样题、评分与报考规则 | 分项正确率、计时模考、官方通过线 |
| `technical-project` | 编程、工具、产品或项目交付 | 可运行的小任务、调试和迁移任务 | 当前官方文档、规范、版本说明与接口要求 | 可运行交付物、测试、真实约束下的演示 |
| `career-transition` | 转行、岗位能力、作品集 | 真实岗位任务、已有作品和迁移能力 | 职业标准、执业要求、当前岗位任务证据 | 作品集、任务模拟、外部评审量表 |
| `language-expression` | 语言、写作、演讲和表达 | 可理解输入、限时输出、理解、迁移与纠错 | 官方等级描述、考试说明、评分量表和适用的二语习得证据 | 可观察的理解、表达、互动、迁移和纠错能力 |
| `theory-academic` | 理论、通识、研究和正式课程 | 概念解释、论证、问题迁移 | 培养要求、课程标准和相关一手研究依据 | 概念图、复述、论证、研究或课程考核 |
| `business-entrepreneurship` | 商业、创业、收入和市场验证 | 客户问题、交付能力和已有需求证据 | 官方工具资料、行业规则、真实客户或交易证据 | 可控交付物、验证实验和外部结果记录 |
| `exploration` | 尚不知道方向或目标成果 | 小型体验任务、偏好与约束证据 | 各候选方向的适用一手资料 | 1–2 周探索冲刺和继续/换向/停止决定 |

不要用固定“学习风格”给用户分类。阅读、视频或实践偏好只影响材料呈现，不得替代真实任务和验收证据。

## 第一性原理拆解

第一性原理拆解用于确定“真正要达成什么、什么决定结果、什么不可绕过、什么只是未经验证的惯例，以及最小如何验证”，不是通用哲学课程。

按目标调整重点：

| 目标类型 | 优先拆解的问题 | 快速通过条件 |
|---|---|---|
| 考试与认证 | 官方通过标准、分项权重、资格与批次是否才是真实边界 | 当前官方范围、版本和通过标准明确 |
| 技术与项目 | 用户结果、输入输出、运行环境、失败边界和最小可运行闭环 | 项目契约、环境和验收样例完整 |
| 转行与职业 | 真实岗位任务、作品证据、招聘外部变量和可控能力 | 岗位任务与作品评审标准明确 |
| 语言与表达 | 使用情境、受众、可观察输出和纠错反馈 | 等级描述、输出任务和评分量表明确 |
| 理论与学术 | 核心问题、解释或论证能力、迁移情境 | 课程要求或研究问题与考核明确 |
| 商业与创业 | 客户问题、价值交付、需求证据、可控实验与外部结果 | 已有真实客户问题和可判定验证实验 |
| 探索型 | 候选方向、低成本代表任务和继续/换向/停止证据 | 不快速通过；必须先形成短期探索闭环 |

若用户把工具、课程或证书当成目标，先询问使用它要改变什么结果。若流行说法不会改变能力链或验收，不必争论；若会导致大量无关学习，把它列为待验证假设。

输出简短“第一性原理摘要”，并合并进目标卡：

- 目标本质与成功证据
- 关键结果变量
- 不可绕过的底层能力与约束
- 待验证假设
- 最小验证闭环
- 当前排除的非阻塞内容

不要把外部市场、招聘、平台分发或他人决定伪装成用户可控变量。不要把“理解底层”本身当成成果，除非理论理解就是已确认目标。

## 探索型目标

当用户还不能确定可观察成果时，先建立 1–2 周探索冲刺，不生成伪精确的长期路线。冲刺必须包含：

- 最多 2–3 个候选方向
- 每个方向一个低成本代表性任务
- 明确投入上限
- 体验记录与能力证据
- 继续、换方向或停止的判断标准
- 冲刺结束后重新制作并确认目标卡

探索冲刺仍需目标卡确认和输出模式选择，但不得把候选方向包装成已确认长期目标。

探索冲刺默认保持紧凑。方向尚未确定前不要搜索或推荐完整课程；优先使用不依赖特定课程的代表性任务。只有某个任务必须依赖具体工具时才核验对应官方资料。依据表可以记录已确认目标卡、诊断证据和必要工具资料，不要为了填表虚构外部来源。

## 商业与外部结果

对收入、就业、晋升、获客或市场成功等目标，分开记录：

- **可控能力与交付物**：用户能够学习、制作和验证的内容
- **外部结果指标**：收入、录用、客户购买或平台分发
- **Skill 可规划部分**：能力、作品、实验和反馈周期
- **不可承诺部分**：市场、招聘方、客户或平台最终决定

路线可以安排需求访谈、销售实验、作品投递和数据复盘，但不得承诺外部结果。验收同时记录过程证据与外部结果，不用单次结果反推全部能力。

## 高风险领域修正

只有目标涉及向他人提供专业建议、实际执业、受监管资格、真实高风险操作，或错误可能造成明显人身、财产、法律或安全损害时，才视为高风险目标。一般知识、历史、理论、考试常识或个人素养学习不因主题名称自动触发高风险门。

高风险目标执行以下修正：

1. 先确认适用国家或地区、目标角色和是否涉及实际执业。
2. 优先核验当前监管要求、资格标准、官方课程和监督要求。
3. 明确区分学习完成、考试通过、取得资格和可独立执业。
4. 不把路线当作资格证明、专业意见或现场监督的替代品。
5. 若地区、监管要求或监督条件不明确，只问一个决定性问题，不生成正式路线。

## 依据选择与时效

从目标卡建立证据需求。每份入选材料必须直接支持至少一项：

- 学习范围或明确排除项
- 版本、地区或考试批次
- 必要能力及依赖
- 验收、评分或通过标准
- 工具、环境、安全或合规约束

使用四级来源：

1. 当前适用的官方标准、大纲或规范
2. 官方文档、教程、样题和产品资料
3. 专业机构、学术组织、真实岗位或任务证据
4. 教材、课程及其他学习资源

输出依据表：

`来源｜等级｜支持的结论｜版本/地区｜核验日期｜访问状态｜置信度`

遵守以下规则：

- 把官方但无关的材料放进“暂不采用”。
- 官方依据不足时按等级补足，不把补充材料描述成官方结论。
- 冲突时先核对目标、版本、地区、时间和适用场景；无法可靠取舍时暂停路线并只问一个问题。
- 无法联网时使用用户提供的一手材料并标注“未实时核验”，不得虚构链接、版本或价格；若缺失内容不改变关键决策，继续产出带适用边界和后续核验动作的路线。
- 首次正式路线必须核验关键来源。
- 结构性重排必须复核考试要求、产品版本、价格、访问条件等易变化内容。
- 恢复路线时，易变化来源超过 30 天未核验、链接失效或版本不明时先复核；稳定标准只在版本或适用性存疑时复核。

使用以下停止条件：学习范围、适用版本或地区、能力依赖、验收标准和关键约束都已有足够依据，且新增材料不会改变范围、顺序、资源或验收决策时，停止检索。不要为了让依据表更长而继续搜索。

不能用“仍可找到更多资料”拖延已经有足够证据的规划，也不能用“信息不完整”拒绝处理不受该缺口影响的部分。只有来源缺口会改变范围、版本、合规、安全、能力依赖或验收时才暂停，并明确说明受影响的决定。

技术项目、开源工具和工程实践目标确有需要时，可以搜索 GitHub 高 Star 项目发现候选实现、工具或真实任务证据。Star 只表示关注度，不表示权威、安全、质量或适用性。采用前检查：

- 是否与目标和当前技术栈直接相关
- 是否来自官方组织；官方仓库可按内容归入第 2 级，社区仓库通常只作为第 3 或第 4 级补充
- 最近提交、正式发布和维护状态
- 文档、示例、测试和迁移说明是否完整
- 许可证是否允许预期用途
- Issue 与安全公告是否暴露阻塞性问题
- 版本、平台、语言、设备和依赖是否兼容

高 Star 但长期停更、许可不明、版本不兼容或与目标无关的项目放入“暂不采用”。不得仅按 Star 排名推荐，也不得用社区仓库覆盖当前适用的官方规范和文档。

## 具体内容深度

内容颗粒度由目标成果决定，不由“全面学习一门学科”的惯性决定。先拆最终作品、题型、任务或场景，再选择恰好足以完成它的知识。宽泛主题名只能作为分组标题，不能作为路线的全部学习内容。

| 目标类型 | 必须展开的具体内容 | 默认减少的内容 |
|---|---|---|
| 考试与认证 | 当前大纲条目、题型能力、具体概念或规则、权重、常见干扰与计时要求，并映射到样题和评分标准 | 超纲理论、与当前批次无关的旧内容 |
| 技术与项目 | 项目模块、输入输出、运行约束、数据或接口、所需语言特性与库、异常和边界、测试、日志、交付方式 | 与目标无关的语言全景、框架大全和提前优化 |
| 转行与职业 | 真实岗位任务、工具操作、判断标准、作品模块、协作与评审要求 | 不能形成岗位证据的泛知识 |
| 语言与表达 | 使用场景、语言功能、可理解输入范围、高频词块、必要语音与语法、理解与输出任务、纠错点和评分量表 | 低频且不服务目标场景的全量词表、语法目录和被动输入时长 |
| 理论与学术 | 核心问题、关键概念、概念关系、必要命题或方法、代表问题、论证或研究产出 | 不能支撑当前问题或考核的旁支历史 |
| 商业与创业 | 当前客户问题、交付物、最小必要知识、验证动作、反馈数据和决策标准 | 与当前实验无关的完整商业课程 |
| 探索型 | 每个候选方向完成代表任务所需的最小知识和体验证据 | 尚未选择方向的完整课程与长期知识树 |

技术项目必须先形成模块映射：

`项目模块｜输入、输出与约束｜具体知识点与子技能｜实现与练习任务｜典型错误与边界情况｜测试与验收｜暂不包含`

例如“学习 Python 基础”不是合格内容；应根据目标写成支撑具体模块的变量与数据结构、控制流、函数、文件或表格读写、异常处理、测试等，并明确哪些当前不需要。不是所有 Python 项目都需要这些内容，只有实际模块依赖时才纳入。

学科型目标的每项内容至少回答三个问题：它具体是什么、它支撑哪个目标任务、怎样用任务证明学会。商业、自媒体与探索型目标不需要模仿教科书深度；只保留完成当前作品、实验或决策所需的知识。

分层版详细展开当前阶段的全部内容映射，后续阶段保留关键模块和知识点，不得退化成只有阶段名称。全量版详细展开所有阶段，但仍删除不阻塞目标的内容。教材章节、页码、课程单元和软件版本只有在实际访问并核验后才可写出；否则写知识点、筛选标准和待核验状态。

### 语言学习的高效闭环

语言目标默认使用下列闭环，不按学校教材目录平均推进：

1. **目标场景**：先确定要听懂、说出、读懂或写出什么，以及对象、速度、长度和质量标准。
2. **可理解输入**：选择大部分内容可以通过上下文理解、但包含少量新词块或表达的材料；难到只能逐词翻译时先降级，不把完全听不懂称为沉浸。
3. **主动提取**：只提取目标场景中高频、可复用或反复阻塞的词块、语音对比和语法规律，用回忆、重组和间隔复测巩固。
4. **有意义输出**：用复述、问答、写作、角色任务或真实沟通重组输入，不以照读、抄写或看完作为通过。
5. **纠错与再输入**：根据可获得的最强反馈定位影响理解或表达的错误，再选择针对性输入和练习。
6. **变式迁移**：更换说话者、主题、语速、文本、受众或沟通限制，证明能够在新情境使用。

不要把“可理解输入”误写成只输入不输出。输入建立语言模型和语境，主动回忆、输出、反馈和迁移证明能用。语法与词汇不完全排除：只在它们直接阻塞理解、准确表达、目标题型或评分标准时显式学习。

用可观察指标判断效率：

- 首次和重复接触后的主旨、细节或指令理解
- 不看原文的复述、回答或重组质量
- 目标任务完成度、流利度、准确度和可理解度
- 同类错误复发率
- 7/30/90 天或目标适用节点的保持与迁移

输入难度不要套固定百分比。根据材料类型、目标和当前证据逐步调整：能完成主旨任务但仍有少量可推断新内容时继续；因未知内容无法理解主旨时降级；几乎没有新内容且任务稳定通过时升级。

考试型语言目标仍以当前官方大纲、题型、时间和评分量表定义范围与验收。可理解输入和任务练习用于更高效地掌握这些能力，不能替代官方要求或漏掉必须题型。

## 以做促学

路线默认从最小代表任务开始，而不是从课程第一章开始。任务必须足够小、可在当前条件下完成或安全失败，同时覆盖目标的一条最小闭环。

使用七步循环：

1. **先做基线任务**：在不补新知识前尝试代表任务，记录结果、时间和失败点。
2. **定位阻塞缺口**：判断是概念、操作、练习、反馈、环境还是约束问题。
3. **即时学习最小知识块**：只读取能解决当前缺口的官方说明、示例或必要解释。
4. **立即用于产出**：在同一学习周期内修改作品、代码、答案、论证、表达或实验。
5. **获得可检查证据**：运行测试、按量表评分、提交评审或记录真实结果。
6. **针对反馈修正**：只修复失败的部分，不用继续看课代替修改。
7. **更换条件再做**：用新数据、题目、受众、约束或场景验证迁移。

不同目标的“做”：

| 目标 | 最小代表任务 | 学习后的立即应用 |
|---|---|---|
| 考试 | 一组覆盖目标题型的诊断题 | 解释错因并完成同概念变式题 |
| 技术项目 | 可运行但功能最小的端到端切片 | 实现一个模块并让测试通过 |
| 职业转行 | 一项真实岗位模拟任务 | 修改作品并按岗位量表复评 |
| 语言表达 | 一次目标场景理解或表达任务 | 复述、对话、写作或真实沟通 |
| 理论学术 | 一个代表问题、解释、推导或小实验 | 重建论证、解题、写短文或复现实验 |
| 商业创业 | 一个客户问题访谈、样品或报价实验 | 修改交付物并再次获得真实反馈 |
| 探索型 | 每个候选方向一个低成本代表任务 | 用体验和结果更新继续、换向或停止决定 |

若内容只产生“看过、收藏、抄过、记过”，没有近期应用和证据，则不进入正式计划。必要前置知识也要拆成能快速应用的小块。目标导向不等于反智或只学技巧：当概念、原理或完整推导直接决定目标质量时，它就是阻塞项，必须通过实际问题或创作产出深入消化。

高风险目标只使用模拟、沙盒、受监督或法规允许的任务。不得把真实患者、客户资产、危险设备或受监管执业当作无监督练习环境。

## 学习有效性闭环

对直接决定目标成果的关键能力，依次确定目标迁移层级、可获得的最强适用反馈和延迟复测。不要让所有阶段机械达到最高级；阶段只需证明达到当前目标所需层级，最终关键能力才要求真实迁移。

### 能力迁移阶梯

| 层级 | 可观察任务 | 适合作为通过证据 |
|---|---|---|
| 1. 引导模仿 | 在提示、范例或步骤指导下完成 | 仅证明能跟随，不证明独立掌握 |
| 2. 独立复现 | 不看步骤独立完成同类任务 | 基础技能或阶段性前置能力 |
| 3. 变式应用 | 在条件、数据、题型或表达对象变化后完成 | 多数考试、技术、语言和理论关键能力 |
| 4. 真实迁移 | 在真实约束、真实项目、真实沟通或现场任务中完成 | 项目、职业、商业和实际使用目标 |
| 5. 边界解释 | 解释何时适用、何时失效、怎样取舍并处理反例 | 高阶专业能力、复杂决策和需要教学或评审的目标 |

路线为每项关键能力标注一个目标层级。只有完成对应层级任务才算通过；跟着教程或答案复现不能被写成“已掌握”。进入下一阶段只要求当前阶段的目标层级，不为追求完整而增加不服务最终成果的任务。

### 反馈质量阶梯

| 层级 | 反馈来源 | 适用方式 |
|---|---|---|
| 1. 自检 | 清单、反思、自己解释 | 低成本初筛，不单独证明真实效果 |
| 2. 客观反馈 | 测试、答案、评分量表、静态检查或自动化结果 | 可重复检查正确性和稳定性 |
| 3. 同伴反馈 | 同水平或协作伙伴的审阅、互测和对话 | 发现表达、协作和使用盲点 |
| 4. 专家反馈 | 老师、教练、资深评审、代码审查或专业审核 | 校正高难度判断、质量和行业标准 |
| 5. 真实环境反馈 | 真实用户、客户、工作现场、正式考试或生产运行 | 验证最终迁移和外部适用性 |

选择当前能获得且与目标匹配的最高层反馈，不强迫用户购买昂贵服务或寻找不存在的评审。高层反馈不可获得时，使用次强方案并明确降低通过结论的置信度；不能把自检或 AI 建议伪装成专家、用户或正式考试结果。记录反馈层级、来源、日期、发现和据此修改的内容。

### 延迟复测

默认节点的含义：

- **7 天**：不看原步骤，独立回忆或复现
- **30 天**：在变化的题目、数据、受众或约束中应用
- **90 天**：在真实场景中迁移，并解释适用边界

按目标调整：

| 目标 | 复测规则 |
|---|---|
| 项目、职业、语言和需长期保持的能力 | 关键能力初次通过后默认安排 7/30/90 天复测 |
| 考试与认证 | 把累计复测放在考试前；若“通过考试”是唯一目标且时间不足，不为形式安排无用的考后 90 天保持 |
| 理论与学术 | 对核心概念安排 7 天回忆、30 天迁移；研究或长期课程需要时再安排 90 天综合任务 |
| 商业与创业 | 复测可用新客户、新约束或下一轮实验，不把市场结果波动直接当成能力退化 |
| 探索型目标 | 不设置伪精确的 7/30/90 保持计划；在冲刺结束时重新检查方向证据和决策标准 |

期限不足 90 天时，只把截止日前可执行的节点纳入当前计划；其余标为截止日后可选保持任务。截止日前的复测必须计入计划时间，截止日后的维护不占当前预算。复测失败时定位遗忘、变式或真实迁移缺口，安排最小补救任务后再次复测；不要自动重学整个阶段。

## 学习方法选择与负荷控制

路线只决定学习方法是否适用、用于哪项能力、放在哪个阶段、需要什么反馈和怎样验收。不要在路线中展开逐题教学、分钟级练习序列、提示话术或即时纠错；这些属于实际学习执行。

### 阶段认知负荷

控制宏观学习负荷，不给用户贴固定认知能力标签：

- 按前置依赖拆开同时出现的全新概念、操作、工具和环境；一个任务因新元素过多而失败时，先减少同时变化的维度，再逐步重新组合。
- 每阶段保持一条主线和最多一个辅助主题；高复杂成果拆成可独立产出和验收的模块，但最终仍回到完整任务验证迁移。
- 起点证据不足或任务复杂度估算置信度低时，先安排短周期诊断任务并重新估算，不用长期简化代替能力提升。
- 路线可以注明需要范例、脚手架或提示递减，但不编写具体讲解与提示流程。

### 瓶颈优先，而非机械 80/20

优先处理直接阻塞目标、验收权重高、当前缺口大、真实任务中高频或能解锁多个下游能力的内容。可用“目标影响 × 缺口程度 × 使用频率 ÷ 时间成本”帮助比较，但只能作为定性启发，不输出伪精确分数。

80/20 不是固定比例。考试必考项、安全与合规要求、严格前置知识和低频但高损失的边界情况不能因为“不属于高频 20%”而删除。没有证据表明某项是瓶颈时，先用最小任务验证，不凭流行说法决定优先级。

### 刻意练习成立条件

只有同时满足以下条件时才称为刻意练习：

1. 针对一个有证据的具体薄弱子技能。
2. 难度略高于当前稳定水平，但仍可通过努力完成。
3. 有清晰、可观察的成功标准。
4. 能获得及时且适用于该能力的反馈。
5. 根据错误进行针对性修正，而不是机械重复。
6. 修正后再次尝试，并记录错误类型与改进证据。

路线记录：

`薄弱子技能｜当前证据｜练习任务与难度变化｜反馈来源｜成功阈值｜修正与重试条件`

缺少可信反馈、明确标准或针对性修正时，写“针对性练习”，不要夸大为刻意练习。路线负责定义练习契约，不负责逐次出题和现场提示。

### 交错学习启用条件

仅在学习者已经能分别完成相关基础任务，并且目标需要辨别“何时使用哪种方法”时安排交错练习。优先用于容易混淆的题型、概念、错误模式、数据、受众或场景，让学习者练习识别线索和选择策略。

以下情况暂不交错：

- 单项基础任务尚不能独立完成
- 技能存在尚未满足的严格前置依赖
- 多个新元素同时出现已造成明显负荷过高
- 高风险操作尚未在模拟或监督条件下稳定
- 混合任务只增加难度，不产生辨别或迁移价值

路线写明开始交错的进入条件、混合维度、目标辨别能力和通过证据；不要生成具体题目排列。达到条件前使用成组练习稳定基础，达到条件后再逐步增加交错比例，不机械要求所有内容交错。

## 路线与阶段契约

先建立三层成果：

- **最小可达成果**：期限紧张时仍能交付
- **已确认目标成果**：唯一正式排期对象
- **可选扩展成果**：不占用当前时间预算

只安排已确认目标成果。通常使用 3–5 个阶段，每阶段最多一条主线和一个辅助主题，并包含：

- 阶段目标与 3–6 个必要主题
- 前置条件和进入条件
- 主动练习与真实产出
- 目标迁移层级及对应任务
- 最强适用反馈层级、来源与记录方式
- 验收量表、通过阈值和所需证据
- 未通过时的补救动作
- 预计小时范围与高、中或低估算置信度
- 进入下一阶段的条件

估算置信度低时使用偏保守时间，把首个检查点设为重新估算节点。每阶段默认一个主资源、最多一个补充资源。

根据目标选择主动回忆、间隔复习、刻意练习、交错练习、反馈和迁移任务，不强行全部使用。按照本文件的成立条件区分刻意练习与一般针对性练习，并在基础稳定后才启用有辨别价值的交错练习。阅读或观看必须服务于练习，不能作为通过证据。对关键能力应用本文件的迁移、反馈与延迟复测规则。

最多展示三个关键风险。每个风险写明触发条件、早期预警和应对动作。

每个检查点记录六项路线效果证据：

- 计划时间与实际时间
- 任务完成率
- 阶段验收通过率
- 主要卡点类型
- 主资源对完成任务的帮助程度
- 当前时间与难度估算是否需要调整

用这些证据决定微调任务量、补救知识缺口或结构性重排；不要只依据“感觉太难”推翻阶段。

## 输出模式

两种模式都必须按 `SKILL.md` 规定的精确标题与顺序输出，不得合并、改名或省略；无内容时写明原因。主路线必须在每个阶段保留时间与置信度、主题与前置、练习与产出、验收阈值与证据、失败补救和进入条件。

### layered

完整展示目标、依据、总路线、时间和验收。详细展开当前阶段及首周；后续阶段紧凑展示阶段目标、依赖、产出、时间范围和通过标准。

### full

展开所有阶段的主题、前置、练习、产出、资源、时间和验收。日级或学习次数级计划仍只展开首周，不生成不可维护的长期逐日安排。

只有时间、成本、资源或目标深度存在真实取舍时才提供一个备选路线，并写明切换条件。
